# CLAUDE.md structure

Claude Code loads these automatically, all merged into context:

1. `~/.claude/CLAUDE.md`: global, private, applies to every project
2. `<project-or-parent>/CLAUDE.md`: checked into the repo, walks up the directory tree
3. `~/.claude/projects/<proj>/memory/MEMORY.md`: auto-memory index (see [05-memory.md](05-memory.md))

Ready-to-edit version: [`templates/CLAUDE.md`](../templates/CLAUDE.md).

## My global file, section by section

Order matters: the most behavior-shaping content is first.

| Section | Purpose |
|---|---|
| **Agent Behavior** | Think before coding, simplicity first, surgical changes, goal-driven execution, context continuity, no scope creep |
| **Environment** | OS, shell, where projects live, what is on PATH. Includes cross-OS warnings because I dual-boot |
| **Stack Selection** | Questions to ask + a decision table, so Claude does not default to one framework |
| **Code Style** | Comment policy, no dead code, follow the repo |
| **UI/UX Rules** | Mobile-first, real content, no lorem ipsum |
| **Git** | Commit cadence, push only when asked, deploy-via-git rules |
| **Browser Automation** | Which tool drives the browser and which is debug-only |
| **Web Projects: SEO & GEO** | A checklist applied to every public web build |
| **Second brain** | Where notes live and when to read/write them |
| **Graphify** | Which graph belongs to which project, and the rule to query before reading |

## Patterns that work

- **Rules as imperatives with a reason.** "Push only when asked" beats "be careful with git".
- **Exact message formats for corrections.** My scope-creep rule scripts the sentence Claude must say ("We're currently doing X. This would expand scope. Finish first, or pivot?"). Scripted phrasing gets followed more reliably than a vague "flag it".
- **Tables for lookups, prose for judgment.** Known-graphs list and stack table are tables. Behavior is prose.
- **A line-count cap.** The file says "keep under 250 lines. Trim before adding." A bloated CLAUDE.md dilutes every rule in it.
- **Global vs project split.** Global = how I work. Project = what this codebase is (build commands, conventions, team rules).
- **Pointers, not copies.** Big reference material (a client knowledge base) lives in files; `CLAUDE.md` says *when to read it*, not the content.

## Gotchas

- Two files with overlapping rules will drift. I have a global one and a copy checked into my drive root; the older copy still says Windows/PowerShell. Keep one source of truth or accept the drift.
- Anything auto-generated by a plugin's `init` (I have a Ruflo block) gets appended to project files. Review it. Delete what you do not use.
- Do not put secrets in `CLAUDE.md`. It is loaded into every prompt and often committed.
